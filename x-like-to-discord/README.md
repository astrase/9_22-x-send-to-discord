# X Like to Discord — 初心者向けガイド

X（https://x.com）で、自分が投稿のハートをクリックしたときに、その投稿のURLをDiscordへ自動送信する拡張機能です。X API、Bot、外部サーバー、月額API契約は不要です。設定したDiscord Webhookだけに送信します。

送信内容：

```
❤️ Xでいいねしました

https://x.com/username/status/123456789
```

## 1. 最初に準備するもの

- パソコンのChrome（102以上）またはFirefox（140以上）。最新の安定版を推奨します。
- Xにログインしたブラウザ。
- Webhookを作成できる権限があるDiscordサーバーとテキストチャンネル。
- このZIPを展開したフォルダー。ZIPを開くだけではなく、Windowsなら右クリック →「すべて展開」を選びます。

プログラミングの準備やビルドは不要です。生成済みの `chrome` と `firefox` フォルダーを使います。

## 2. Chromeへのインストール

1. アドレスバーに `chrome://extensions` と入力します。
2. 右上の「デベロッパーモード」をオンにします。
3. 「パッケージ化されていない拡張機能を読み込む」を押します。
4. 展開した `x-like-to-discord` の中の **chromeフォルダー** を選択します。親フォルダーやZIPを選ばないでください。
5. ツールバーのパズルアイコンから「X Like to Discord」を押すと設定画面が開きます。拡張機能の「詳細」→「拡張機能のオプション」からも開けます。
6. 開いていたXのタブを再読み込みします。

このフォルダーはインストール後も移動・削除しないでください。変更後は拡張機能一覧の再読み込みボタンを押し、Xのタブも再読み込みします。

## 3. Firefoxへのインストール

1. アドレスバーに `about:debugging#/runtime/this-firefox` と入力します。
2. 「一時的なアドオンを読み込む」を押します。
3. 展開した **firefoxフォルダー内のmanifest.json** を選択します。
4. ツールバーの拡張機能メニューから「X Like to Discord」を押し、設定画面を開きます。`about:addons` の該当拡張機能の設定からも開けます。
5. Xへのサイトアクセス許可が求められた場合は許可し、Xのタブを再読み込みします。

**一時的なアドオンはFirefoxを終了すると解除されます。** 再起動後は読み込み直し、設定を確認してください。通常版Firefoxに恒久インストールするにはMozillaによる署名が必要です。このZIPは未署名なので、通常のアドオンとして直接インストールできません。最初は一時読み込みで試してください。

ChromeとFirefoxの設定・履歴は共有されません。同時に使用した場合のブラウザをまたぐ重複は防止できません。

## 4. Discord Webhookの作成

1. Discordで送信先のサーバーを開きます。
2. 送信先テキストチャンネルの歯車（チャンネルの編集）を押します。
3. 「連携サービス / 連携」→「ウェブフック / Webhook」を開きます。
4. 「新しいウェブフック」を作成します。
5. 名前（例：Xいいね保存）と送信先チャンネルを確認し、必要なら保存します。
6. 「ウェブフックURLをコピー」を押します。

メニューがない場合は「ウェブフックの管理」権限を持つ管理者に相談してください。Botの作成やBotトークンは不要です。最初は自分だけが見られるテスト用チャンネルをおすすめします。

## 5. Webhook URLの設定

1. 拡張機能の設定画面を開きます。
2. コピーしたWebhook URLを貼り付けます。
3. 「いいねした投稿URLをDiscordに自動送信する」にチェックを入れます。
4. 「保存」を押します。
5. 「Discord接続テスト」を押します。
6. Discordに **X → Discord連携テスト成功！** が表示されれば接続できています。

テストは保存済みURLを使い、自動送信をオフにしていても実行できます。Webhook URLは `https://discord.com/api/webhooks/…` 形式を使用します。別ドメインやクエリ付きのURLは受け付けません。フォーラム・スレッド指定などの追加パラメーターが必要なWebhookには対応していません。

自動送信を止めるにはチェックを外して保存します。URLを削除するには入力欄を空にして保存します。

## 6. 動作確認

1. Xのページを再読み込みし、まだいいねしていない投稿のハートをクリックします。
2. 右下に「✓ Discordに保存しました」と表示され、Discordに正しい投稿URLが届くことを確認します。
3. 同じハートをもう一度押していいねを解除します。新しいメッセージが届かなければ正常です。
4. すぐに再いいねします。「送信済み」の通知が出て、二重送信されないことを確認します。
5. タイムラインをスクロールして追加読み込みした投稿、X内でページ移動した先、投稿の詳細画面でも確認します。
6. 引用投稿では、いいねを押した側の投稿URLになっていることを確認します。

キー操作が通常のclickイベントを発生させる場合も検知しますが、X独自のキーボードショートカット、ダブルタップ、アプリや別端末からのいいね、過去のいいねの一括取得は対象外です。

## 7. 二重送信と再いいねの扱い

初期設定は **同じ投稿IDの送信成功から24時間は再送しない** です。設定の「再送を防ぐ時間」を1〜8760時間（1年）で変更できます。期間を過ぎてからもう一度解除→いいねした場合には送信します。解除しても既存のDiscordメッセージは削除しません。

判定は `core.js` の `duplicate()` と `DEFAULT_HOURS` にまとめています。さらに細かな扱いを変える場合はここを修正できます。履歴は投稿ID・時刻・送信状態をstorage.localへ保存し、1年を超えたものを次の送信時に整理します。

複数のXタブからの送信はバックグラウンドで直列処理します。送信前にも2分間の予約を保存します。ただしDiscordに届いた直後のブラウザ強制終了や通信切断では、到達したかを確定できません。厳密な「必ず1回だけ」の配信保証はありません。失敗時の自動再送は行わず、Discord側を確認してから再度いいねしてください。未確定時は2分待ってください。

## 8. よくあるエラー

| 症状 | 確認すること |
| --- | --- |
| 何も起きない | 自動送信のチェックと保存、拡張機能の有効化、Xへのサイトアクセス許可、Xタブの再読み込みを確認します。URLがx.comか確認します。 |
| Webhookを設定してください | 設定を保存してください。ChromeとFirefoxは別設定です。 |
| HTTP 401 / 403 / 404 | Webhookが削除・無効化されていないか確認し、新しいURLをコピーして保存します。 |
| 送信制限中 / HTTP 429 | Discordの制限です。少し待って再度お試しください。応答のretry_afterを使って送信を抑止します。 |
| 通信結果を確認できない | オフライン、ファイアウォール、15秒のタイムアウトなどが考えられます。Discordに既に届いている可能性もあるので確認します。 |
| 投稿URLを取得できない | 投稿の詳細画面で試します。引用やDOM変更で曖昧な場合は安全のため送信しません。 |
| いいねの反映を確認できない | Xが未ログイン・通信エラー、またはDOM変更の可能性があります。4秒以内に表示が変わる必要があります。 |
| 送信済みと表示される | 重複防止期間内です。別の投稿で試してください。 |
| 再読み込み後に拡張機能が動かない | 拡張機能を更新したらXも再読み込みします。Firefoxの一時アドオンは再登録が必要な場合があります。 |
| DiscordにURLだけでプレビューがない | プレビュー表示はDiscordとX側の挙動や閲覧権限に依存します。URL送信自体は成功している場合があります。 |

## 9. セキュリティ・プライバシー

Webhook URLはそのチャンネルへの投稿権限に相当する秘密です。スクリーンショット、GitHub、チャットに貼らないでください。漏れたらDiscordでWebhookを削除し、新しく作り直します。

設定はブラウザの `storage.local` に保存します。クラウド同期しませんが、暗号化された秘密保管庫ではありません。PCやブラウザプロファイルにアクセスできる人には見られる可能性があります。コードはURLをログに出しませんが、開発者ツールのネットワーク表示には通信先が含まれ得ます。

この拡張機能のネットワーク送信先はDiscordだけです。Xの既存ページのDOMを読み、X APIは呼びません。送信するのは固定文と投稿URLで、Cookieや本文・画像を読み出して送信しません。Discordは送信先サービスとしてメッセージを処理します。URLに作者のユーザー名が含まれ、チャンネル参加者にいいねした事実が伝わります。非公開アカウントの投稿でもURLは送られるため注意してください。

権限はstorageとDiscordへのホストアクセス、Xに限定したcontent scriptです。tabs、cookies、webRequest、全サイトアクセス、外部ライブラリは使いません。ホスト権限ではパスが厳密な境界にならないためDiscordホストを指定し、コードでWebhookパスを検証します。リダイレクトは拒否します。Chromeではstorageのアクセスを拡張機能側に制限し、両ブラウザとも設定の取得・変更・テストは設定画面からだけ許可します。

FirefoxのManifestは、送信する操作情報とWebhook認証情報に対応するデータ種別を宣言しています。ストアへの公開審査・署名取得は実施していません。

## 10. ファイル構成と変更方法

```
x-like-to-discord/
├── chrome/              Chromeに読み込む完成版
│   ├── manifest.json
│   └── 共通ファイル6個
├── firefox/             Firefoxに読み込む完成版
│   ├── manifest.json
│   └── 共通ファイル6個
├── core.js              URL検証・重複判定
├── content.js           いいね検知・投稿特定・通知
├── background.js        設定・送信・履歴・送信制限
├── options.html         設定画面
├── options.js           設定画面の操作
├── options.css          設定画面の見た目
├── build.py             両ブラウザ向けフォルダーの再生成
├── tests/               Node.js標準機能による自動テスト
├── REVIEW.md            検証結果・残る制約
└── README.md
```

アイコンは省略し、ブラウザの既定表示を使用しています。

Xの仕様変更で動かなくなった場合は、まず `content.js` を確認します。

- `data-testid="like"` / `"unlike"` が変更されていないか。
- `article` の範囲と、投稿ヘッダーの `a[href]` 内の `time` が存在するか。
- 引用カードの `data-testid="quoteTweet"` / `role="link"` が変更されていないか。
- いいね済み状態が4秒以内に反映されるか。

CSSの見た目用クラス名には依存しません。documentへのイベント委譲でSPAと無限スクロールに対応します。DOM監視はクリックした投稿について最大4秒だけ行います。表示の更新はXの楽観的更新の場合もあるため、Xサーバーにいいねが保存されたことまで保証はできません。

開発するときだけPython 3とNode.jsが必要です。親フォルダーで次を実行します。

```
python build.py
node --test tests/core.test.cjs tests/background.test.cjs tests/content.test.cjs
```

macOS/Linuxでは `python3 build.py` でも実行できます。ルートのソースを変更後、必ずbuild.pyを実行し、拡張機能とXを再読み込みしてください。

## 12. v1.1.0：Fixupボタン・ダーク／ライト切り替え

### Discordへ送るリンク形式（v1.3.0）

設定画面にある「Discordへ送るリンクをFixup形式に変換する」のチェックで選び、**保存**を押してください。

- ON：いいねした投稿を `https://fixupx.com/username/status/123456789` の形式でDiscordへ送信します。
- OFF：`https://x.com/username/status/123456789` のまま送信します。

初期値・旧版からの更新直後はOFFです。変換用の入力欄とコピーボタンはありません。Xの投稿上にもボタンを追加しません。設定は次に送信する投稿から反映され、既存のDiscordメッセージは変更しません。同じ投稿の重複判定は投稿IDで行うので、設定を切り替えても重複防止期間中は再送されません。確認するときは別の未送信の投稿をいいねしてください。

変換処理そのものは文字列置換のみです。FixupXへの通信は拡張機能から行いませんが、Discordのプレビュー取得やリンクを開く操作ではFixupXが利用されます。

変換形式の公式資料：https://github.com/FxEmbed/FxEmbed

### ダーク／ライト切り替え

拡張機能の設定画面の右上にスイッチを追加しました。オンでダーク、オフでライトになります。切り替えはすぐに保存され、次回開いたときにも復元します。初回はOSの設定に合わせます。このスイッチは拡張機能の設定画面に適用され、X本体のテーマはX側の設定を使います。

### 更新手順

1. ZIPを展開します。
2. Chromeは、最初に読み込んだchromeフォルダーのファイルを新しいchromeフォルダーの内容で上書きし、chrome://extensionsの再読み込みを押します。別の場所から新規登録すると別拡張機能として扱われることがあるので、同じフォルダーを使います。
3. Firefoxは、一時アドオンとして新しいfirefox/manifest.jsonを読み込みます。必要に応じて既存の一時アドオンを削除してから読み込み直してください。設定が残っているか確認してください。
4. Xのタブと拡張機能の設定画面を再読み込みします。

変換判定は `background.js`、URL変換は `core.js` にあります。旧fixup.jsとconverter.jsは不要になりました。

更新後のテストは `node --test tests/*.test.cjs` で全件実行できます。

## v1.3.1：投稿URL取得エラーの修正

「投稿URLを取得できませんでした」と表示される原因になっていた、日時リンク自身のrole="link"まで引用として除外する不具合を修正しました。引用カードはリンクの親要素を調べて除外します。

更新後は拡張機能のバージョンが1.3.1であることを確認し、**Xのタブも再読み込み**してください。エラー時にすでにいいね済みになっていた投稿は、一度解除してから再度いいねするか、別の未いいねの投稿で試してください。
